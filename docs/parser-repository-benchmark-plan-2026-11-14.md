# Parser and evidence repository benchmark — 14 November 2026

## Decision to make

Test external components against the same official Indian filings and ThesisIQ's current pipeline. Promote a component only where it improves source-backed accuracy without creating a new silent failure, unbounded cost, or worker timeout. This benchmark is read-only: it does not change the production parser, database, or Telegram output.

The current local fixes and remaining live-data issues are recorded in [the handoff](handoff-2026-11-13-output-audit.md); the integration sequence is in [the alert-quality plan](alert-quality-implementation-plan-2026-11-14.md). No external candidate has yet passed the full benchmark.

## Execution steps and artifacts

1. **Freeze the baseline.** Save `git status`, local ThesisIQ commit, candidate remote URL/commit/license/dependencies, OS/runtime, model versions and SHA-256 of each source file in a benchmark manifest. Keep clones and virtual environments under the Codex workspace `work/` outside the ThesisIQ checkout. Reuse the three existing clones and Arelle environment; clone the four missing first-wave repositories into separate folders. Do not install their dependencies into ThesisIQ. If a repo needs an external key, paid service, or remote document upload, mark that path `not runnable locally` and evaluate its open offline verifier separately.
2. **Build a hand-checked gold corpus.** Reuse the 62 archived XMLs for crash/coverage tests; select a smaller, independently annotated set of official XML/PDF pairs covering at least five companies (Astra, HBL, HSCL, Time Technoplast and one bank or insurer), several reporting periods, quarter versus YTD, standalone versus consolidated, negative values, units, revisions, segments and missing tags. Obtain the matching official 2026 taxonomy and current FY27-Q2 XMLs, verifying source identity and hash. Add SBCL's 40-page scanned deck, the Time cover plus linked 16-page transcript, SBCL's complete 65,198-character call and at least two ordinary decks and calls. Annotate expected facts, forward targets, cuts, conditions, contrary explanations, source page/turn and exact quote directly from the official document. Hold back some companies from tuning and use them for the final cross-company check.
3. **Run isolated extraction.** For each input, capture raw output and normalized comparison JSON from the current ThesisIQ path and every applicable candidate. Record PDF pages attempted/succeeded, OCR provider/429/Retry-After, transcript character and turn coverage, XBRL validation errors, CPU time, peak memory, external calls and estimated cost. The common harness must distinguish `NOT_APPLICABLE`, `FAILED`, `PARTIAL` and `COMPLETE`; a parse without an exception is not a correctness pass. Each run is restartable and writes a result per document so one bad file cannot erase the batch.
4. **Score claims, not just text.** Compare exact filing identity; fiscal period; quarter/YTD; standalone/consolidated; number, sign, magnitude and unit; revisions; source page/turn; forward versus historical versus conditional guidance; and material context. For the Time case, the verifier must follow the cover link and reject the false claim that the ₹83 crore order is absent. For SBCL, it must find the 55% utilization target and retain the later explanation of the apparent US decline. Report precision and recall separately for material facts/guidance and list each missed or unsupported claim by source. Run a deliberately incomplete PDF, bad link, OCR 429, duplicate filing and worker-restart simulation to test visible deferral.
5. **Decide component by component.** A candidate passes the safety gate only if the gold corpus has zero unsupported material numerical alerts, zero falsely asserted source omissions, no silent partial completion, and no wrong company/period/basis values promoted as verified. It must improve material-fact or guidance recall over the baseline without reducing precision on the held-out companies. Set the latency/cost budget from the measured scanner and worker limits; any candidate that exceeds it can run asynchronously with resumable state, or be rejected. Publish a scorecard with denominators, per-document errors, resource use, license/maintenance risk and a `adopt / borrow design / reject` decision for each candidate. If no candidate passes, retain the current path and implement the missing evidence/coverage controls locally.
6. **Integrate in slices.** First add a raw-source/fact ledger with filing hash, revision, concept/context/unit/dimensions or PDF page/turn and extractor version. Then add the winning XBRL processor behind same-period/same-basis PDF reconciliation; add PDF extraction as a page-aware fallback; add complete, resumable call/guidance extraction and claim verification. Keep uncertain claims out of decisive alerts, but preserve them in retry/review. Give every change a failing regression from a real corpus case and run the repo's ordered lint, heart and full tests.
7. **Shadow run and repair.** Run old and new paths side by side on recent saved filing IDs without writes or Telegram sends. Diff facts, guidance, source links, verdicts, alert text, elapsed time and failures. Fix regressions, then stage a small live rollout with health checks and rollback. Historical reprocessing must be exact-ID, source-hash checked, backed up, idempotent and rate limited across Gemini OCR; honor `Retry-After` with provider-wide concurrency limits, jitter and staged batches so a bulk replay cannot trigger another 429 burst. Review correction drafts before any old alert is resent. Follow `.agents/AGENTS.md` for database mutation and git commit/push boundaries.
