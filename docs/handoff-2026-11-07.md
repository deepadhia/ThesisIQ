# Handoff — the NSE feed returned other companies' filings (2026-11-07)

Builds on `handoff-2026-11-06.md`. Read `.agents/AGENTS.md` first (new invariant **I22**). **Nothing here is committed, pushed, deployed or
written to the database.** Baseline at the start of the session: lint clean, 851 tests green. Now: lint clean, `test:heart` 423, `npm test` 49 files / **880 tests**.

## What was found (all read-only, in this order)
Starting point was the self-audit: 88 filings "stalled", 69 of them 9-12 h old with 0 attempts. Their file names belonged to other companies
(`BIRLACORP1_…`, `ESDS_…`, `LGEINDIA_…`, `ANURAS_…`, `BUILDPRO_…`) but sat under CCL, ELECON, SJS and the other tracked tickers.

* **Root cause (probed live):** NSE's `NextApi … getCorporateAnnouncement` endpoint **ignores `symbol`** and returns the latest 20 filings of the whole
  market, for CCL, for ELECON and for a made-up symbol alike (16 different symbols in one answer). The answer is never empty, so the old
  "empty → legacy per-symbol endpoint" fallback never ran. The scanner saved every row under the stock it was asking about.
* **Scale (live DB, since 2026-11-06):** 533 foreign filings across all 20 tickers (of 560 rows created in the window; the rest are the stocks' own NSE rows, BSE rows and 14 attachment-less HSCL rows, all checked). 102 were already alerted
  (Manyavar, Denta, Buildpro, Anuras, 3i Infotech, Kirloskar filings sent as ANANTRAJ / JYOTICNC / POLICYBZR / LUMAXTECH alerts), 69 are still queued.
  97 commitments trace to foreign filings by text. One quarterly snapshot was written from a foreign filing: **MOREPENLAB Q2_FY27 holds Anupam Rasayan's EPS correction**
  (the real MOREPENLAB results row still needs its re-queue, handoff 11-06 item 3). `stock_syntheses` for ANANTRAJ were regenerated four times in the window.
* **Why nothing stopped it:** no check that a row belongs to the requested symbol; no self-audit for it. It started the evening of 11-06; today is a Saturday, so no new scans ran. **On Monday the old code on Oracle would have flooded again.**
* **Second trap found while fixing it:** stored NSE ids are mostly the **file name** (NextApi era: `seq_id` is null), the per-symbol endpoint returns a **numeric `seq_id`**. With only the fetch fix, every stored filing of the last 30 days would look new
  and be re-ingested (HSCL already shows 14 such re-created rows, all old and silently archived). Dedupe now matches either id.

## Fourth pass (user: "keep fixing, or check GitHub / Reddit / free sites for a concall parser we can inherit")
Suite after it: lint clean, `test:heart` 430, `npm test` 51 files / **917 tests**.
**Research (GitHub public API, web search, Reddit/ValuePickr threads; nothing was run from any of it):**
* **Nothing worth inheriting wholesale.** `JS12540/concall-parser` (MIT, 6 stars, last push 2025-12, Python, Groq llama3-70b-8192) segments a call into management commentary and per-analyst Q&A with ONE LLM CALL PER MODERATOR TURN; its own `docs/issues.md` lists index errors, calls with no moderator, `(cid:45)` glyph damage and "prompt too long" on 8k models. `concall-daily-digest` (no licence: cannot be copied) tracks guidance MET / BEAT / MISSED per company: the idea we already built, on verified statement numbers, which is stronger than its text-only tags. `claude-concall-watch` (MIT) is a weekly local-Ollama summary log. EarningsEdge, AI-Powered-Concall-Summarizer, Earning_Call_iq: no licence. ArthaLens (the Reddit / ValuePickr tool) and the ValuePickr "800 companies" site are not published as code.
* **The one idea taken** (as a re-implementation, credited in the code comment): separate prepared remarks from analyst Q&A. It needs no LLM: on 9 real filed calls of your stocks the host's own sentence "…next question from the line of <name> from <firm>" matched on 9 of 9.
* **Free sites to scrape instead of the exchanges: not better.** Screener, Trendlyne, Tijori, StockEdge only re-host the same exchange PDFs, so none is earlier. SEBI's rules (per press reports; I did not read the regulation text) are audio within 24 h and the written transcript within 5 working days, both filed on the exchanges, which the scanner already polls (recording -> Whisper path for the 24 h one). Screener's robots.txt disallows `/company/source/quarter/*`; I could not read its Terms of Use, so scraping it carries an unchecked terms risk for no gain in speed. A possible use is as a CROSS-CHECK for missed exchange filings, not as a source; not built.
**Built (`concall-highlights.service.js`):**
* `segmentCall(text)`: prepared remarks + one exchange per analyst (name and firm parsed), from the host's introduction. Cue accepted only as host phrasing ("the line of…", or in a Moderator / Operator / Host / Management turn): an analyst's "last question from my end" (real CCL sentence) is not a cue. No cue -> no structure (monologues, decks, Whisper text) -> old equal-split behaviour.
* `splitTranscript` now cuts BETWEEN exchanges (prepared remarks first) using an exact min-max grouping into at most three 20k parts; if a call does not fit, only the longest exchanges are trimmed (start and end kept) until it does, so EVERY analyst stays, instead of dropping the middle 0-20% as before. Checked on all 9 real calls: 9 of 9 later parts now start at a "Moderator:" / "Management:" turn (before: CCL, GRAVITA, POLICYBZR started mid-answer).
* Extractor cap: a transcript keeps up to 160,000 characters (was 60,000 for every document). Live on the real POLICYBZR PDF: 60,884 characters, so the old cap lost only the last 884 (the final answer and "we'll end the call"), cut mid-sentence: a real but small loss. Downstream is bounded (`capContext`, `splitTranscript`).
* Three real calls added as fixtures (ELECON, POLICYBZR, SHAKTIPUMP transcripts in `fixtures/real-layouts/`).
* Not done: telling the model which part is prepared remarks and which is Q&A (the parts now align to it, the prompt does not say so yet); using the parsed analyst list (names, firms, how many analysts asked about a topic) as a signal; the Gemini-audio fallback.
