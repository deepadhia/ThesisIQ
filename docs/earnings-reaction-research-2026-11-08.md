# Earnings reaction research — 8 November 2026

Research scope: event timing, first-party market-data sources and a generic calculation contract. This note does not independently establish final closing prices for the four examples. A live quote, a later rise and the first post-results session return are different observations. Recommendations below are engineering judgements; they are not trading recommendations.

## Calendar finding that changes the answer

Sunday 8 November 2026 is an actual NSE Muhurat trading session, despite being a weekend and a listed holiday. The exchange circular schedules continuous trading from 14:20 IST; non-CAS securities close at 15:30, while CAS securities leave continuous trading at 15:15 and complete closing-auction matching by 15:35. Post-close runs 15:50–16:00. Thus a weekday-only calendar or a Friday-only freshness check loses a valid reaction session. [NSE circular CMTR76941, 19 October 2026](https://nsearchives.nseindia.com/content/circulars/CMTR76941.pdf).

Store actual session schedules, including closing auctions, rather than encoding every day as 09:15–15:30. An intraday provider quote during this session must remain provisional until the relevant closing process and provider finalisation complete. Volume in this short session is not directly comparable to a normal full day.

## Primary data sources and provider contract

The official NSE historical-reports directory links security price/volume archives and daily reports. SEBI's own directory points directly to the NSE security-history page and the BSE historical-price page. These are appropriate sources for reconciling a provider's final EOD bars. [NSE historical reports](https://www.nseindia.com/static/resources/historical-reports-capital-market-daily-monthly-archives), [SEBI equity-cash data directory](https://www.sebi.gov.in/curation/equity_cash_market.html).

Fetch benchmark observations from the exchange's historical index page and use the identical baseline and endpoint dates as the security; do not silently substitute the nearest benchmark date. [NSE historical index data](https://www.nseindia.com/reports-indices-historical-index-data).

For an authenticated broker adapter, Kite's historical API exposes minute through daily candles with timestamp, OHLC and volume, identified by instrument token. Its examples include `+0530` timestamps. Its `continuous` option concerns expired futures, not corporate-action-adjusted equity prices. Account access and permitted data use must be checked before choosing it. [Kite historical API](https://kite.trade/docs/connect/v3/historical/).

Use the exchange's corporate-action records to identify splits, bonuses, dividends and other entitlements across a measured window. Do not assume an arbitrary provider's `close` is adjusted. [NSE corporate filings — actions](https://www.nseindia.com/companies-listing/corporate-filings-actions).

An adapter should return source/provider, exchange, instrument identity (prefer ISIN plus dated symbol mapping), currency, timestamp/timezone, session date, OHLCV, adjustment basis, corporate actions, fetch time and final/provisional state. Preserve immutable source observations so later provider corrections can be explained. A Yahoo fallback, if used, must be labelled Yahoo rather than NSE; this research did not verify Yahoo's current adjustment contract, and its help endpoint returned 429.

## Proposed calculation contract

The event-study literature distinguishes the event window, normal-return model and measured abnormal return; these choices must be explicit. The proposal below is a descriptive product contract, not a claim of statistically established causation. [MacKinlay, *Event Studies in Economics and Finance*, original paper hosted by Boston University](https://www.bu.edu/econ/files/2011/01/MacKinlay-1996-Event-Studies-in-Economics-and-Finance.pdf).

1. **Anchor the event.** Require a source-backed `published_at` in Asia/Kolkata. Retain timestamp precision and source. If only a date is known, mark timing uncertain; do not invent midnight or infer an exact timestamp from database insertion time.
2. **Select the baseline and horizon.** Baseline is the last completed session close before the first eligible reaction session. Define D1/D3/D5 as the first/third/fifth observed eligible trading-session close. For an intraday release, report mixed D0 separately, with the previous close as its explicitly labelled baseline; a minute-bar event-price calculation is a separate metric. Never silently mix the two conventions.
3. **Calculate consistently.** For matching price basis, return in percent is `100 * (endpoint / baseline - 1)`. Benchmark-relative move is security return minus benchmark return, in percentage points. It is descriptive relative performance, not estimated risk-adjusted alpha. Require positive finite inputs and exact dates; missing values stay null with reasons.
4. **Keep observed and projected separate.** If only two sessions have elapsed, D3 and D5 remain pending. Missing or incomplete exchange bars are unavailable, never zero/flat. Do not count a missing security bar as if it did not exist: distinguish provider gaps, suspension and an exchange holiday using the session calendar.
5. **Explain the path.** Display pre-event 5/20-session run-up, first-session open gap, intraday return and total first-session return separately when comparable bars exist. A gap higher followed by selling is materially different from an all-day decline, even if both close at the same return.
6. **Control adjustment basis.** Raw-to-raw returns require an action-free window or explicit action correction. Split/bonus-adjusted price returns and dividend-inclusive total returns are distinct outputs. Never divide adjusted historical close by raw current close. If adjustment metadata or a complex demerger is unresolved, withhold the affected return with a reason.
7. **Match benchmark and volume windows.** Use one configured broad-market benchmark and optionally a documented sector benchmark. Compare volumes against prior comparable sessions; flag shortened sessions instead of treating their small volume as low conviction. Require adequate history and nonzero denominators.
8. **Keep fundamentals separate from market reaction.** Growth versus last year is not a consensus beat. An expectations comparison requires a timestamped pre-event consensus with matching period, scope and metric. Otherwise expectations are **unknown**. Positive fundamentals with a falling stock is a divergence to review, not an automatic buy/sell instruction.
9. **Do not invent why.** Other company announcements, capital actions, macro moves, valuation, liquidity and pre-event positioning can coexist with results. Describe observed timing and source-backed facts; absent direct evidence, label explanations hypotheses.

## Scalable implementation implications

Use a pure reaction calculator behind provider and exchange-calendar adapters. Batch daily histories across the required windows, cache shared benchmark bars once, deduplicate events for the same release, and refresh only pending/provisional horizons. A single latest-price quote cannot replace historical event windows. Rate limits, retries and freshness must be provider-specific and shared across workers rather than multiplied per ticker.

Persist source event identity, selected baseline/session dates, method version, adjustment basis and input-bar provenance alongside calculated metrics. Recompute on a corrected timestamp, corporate action or amended bar. The UI should show both first-session reaction and latest drift with their explicit dates/as-of, so an old result's continuing decline is not presented as today's new earnings shock.

Suggested regression scenarios: after-close Thursday release; intraday Friday release; Saturday release before a Sunday special session; date-only release; incomplete special-session bar; split across a horizon; missing benchmark endpoint; suspended security; provider gap; zero/invalid price; not-yet-observed D5; positive reported growth with no consensus; and revised filing publication time. These scenarios apply to every company.
